### 实测：各级的阈值余量（【实测】）

### ★ 更正 1：R2「L1 退化为单路召回、触发保底 top-1」——**证伪**

L1 **正常返回 k=3 条**，7~9 条过阈值，**没有触发空结果保底**。
先前之所以看到「只过 2 条」，是因为**当时 TEI 宕机**导致部分集合查询失败、池子不完整。
**但 R2 的定性部分成立**：L1 的池只有 **9~11 条**，而 L2/L3 是 **53~154 条** ⇒
**L1 的召回面确实最薄（差 5~15 倍）**。

### ★ 更正 2：R3「路由越多的层级越难达标」——**结论证伪**

机制存在（K 随路由数增大），但**净效果相反**：
最高 RRF 随层级**升高**（L1 0.19 → L2 0.245 → L3 0.304），
因为「路由变多」带来的额外贡献**超过了** K 增大带来的分数压缩。
余量最紧的反而是 **L2 练习（1.8×）**，不是 L3。
⇒ **不能把 K 的机制单独当作缺陷**；它需要与路由数一起看。

### ★ 更正 3：S1「阈值按全表最大权重标定，故层级越轻阈值相对越严」——**实际影响约为零**

实测逐项复现后发现：`max_w` 的来源**通常是该层已经启用的路由**——
例如 L1 短概念查询的 `max_w=2.0` 来自 `semantic(concept)`，而 semantic 在 L1 是启用的。
原因：**给出最大权重的那个类别，同时也决定了该查询落在哪一层**（`is_code→L3`、
`is_exercise→L2`…）。⇒ 该机制**在当前「类别→层级」映射下不产生实际偏差**。
保留为「若将来层级映射变化需复查」的注意项，**不作为现存缺陷**。

## 3. 按 L1/L2/L3 的设计优劣分析

### 3.1 检索策略

**优点**
- **按查询复杂度分配算力**是正确方向：短查询 k=3、跳分解/HyDE/元数据路由，能显著压平均延迟。
- **元数据路由设上限**（L2 ≤2、L3 ≤3）避免了「路由越多越好」的常见误区——路由数增加会同时抬高 RRF 的 K（见 R3），收益递减。

**缺点**
- **S1 是结构性的**：阈值用「全 13 条路由的最大权重」标定，而各层实际启用的路由数差异很大（2 vs 5）。这意味着**同一套阈值常数要同时服务召回面差 2.5 倍的层级**。L1 受此影响最重。
- **S2**：L1 放弃了最高权重路由族，而 L1 又恰好只有 2 条基础路由 ⇒ **L1 的有效召回面是三层里最薄的**。
- **S3**：分级省延迟的收益在「重排全局关闭」时对 L2/L3 是净损失——它们本可以重排。

### 3.2 召回逻辑

**优点**
- **多路 + RRF 融合**的设计本身稳健：不同路由捕获不同信号（语义 / 词法 / 元数据 / 同义词扩展）。
- **路由权重按类别分化**（代码查询给 BM25 2.0、概念查询给 semantic 2.0）体现了对信号质量的判断。
- **`expanded` 权重刻意压低（0.6~0.8）**，承认同义词扩展会引入噪声——这个自我约束是对的。

**缺点**
- **R1 使整条词法通路在变体上失效**，而 `skip_bm25` 全为 False ⇒ **每个层级都在跑一条对 124 类术语无效的路由**。代价不只是「少一路」，还包括：它占用了 RRF 的 K（R3/R4），却贡献 0。
- **R3 + S1 叠加**：L3 路由多 → K 大 → 分数被压低；而阈值按全表最大权重抬高 ⇒ **召回面宽的层级反而更难达标**，与设计意图相反。
- **R2**（已按 §2.7 实测更正）：L1 的池只有 **9~11 条**，而 L2/L3 是 **53~154 条** ⇒
  **L1 的召回面最薄**，且含变体术语时 BM25 那一路归零、最高 RRF 再降 **23%**。
  它**未**退化到「保底 top-1」（正常返回 k=3），但**余量最薄的一层被削掉 1/4 的分数**，
  一旦正确 chunk 只被单路召回，就很容易落到阈值之下。
- **R5**：同义词扩展对中文短查询关闭，而变体问题恰在中文术语上 ⇒ 该剪枝与已知缺陷**正面冲突**。

### 3.3 排序方式

**优点**
- 三重漏斗（RRF 阈值 → `rerank()` 的 `top_n` → `_apply_rerank_threshold`）体现了「宁严勿滥」的取向，且有兜底避免空结果。
- `lightweight_rerank`（L2 候选池 10、L3 30）是合理的分级。

**缺点**
- **P1 是主矛盾**：`top_n` 这道漏斗在明细里不可观测，实测 `#18` 死于此。而它是**纯排序截断**，与阈值语义不同——两者混在一起会让「调阈值」这类动作失效。
- **P3**：`rerank_score` 全 0 时兜底 `top-2` 是一个**隐式的硬截断**，写在阈值函数里、名字上却看不出来。
- **P4**：K 的动态变化让「分数尺度」随路由数漂移，任何以绝对分数为判据的常量（阈值、`min_keep` 的比较）都隐含依赖当时的 K。
- 若 `RERANK_ENABLED=false`（当前），则 L2/L3 的排序**完全由 RRF 决定**，而 RRF 只看排名不看相似度 ⇒ 语义相近但排名靠后的正确 chunk 无法被救回。

### 3.4 查询改写

**优点**
- 同时具备**扩展**（`expand_query_with_synonyms`，正向 + 反向映射）与**归一**（`normalize_synonyms`），方向是对的。
- 有 `SYNONYM_MAP` 单一真源（331 条），避免多处维护。

**缺点**
- **Q1 是核心缺陷**：归一只作用于**文档侧**，query 侧只有「追加」没有「替换」⇒ 两侧口径不同源。这是 R1、P2 的共同根因。
- **Q2**：改写文档使**引用溯源失真**——这是**产品正确性**问题，独立于检索质量。
- **Q4**：`warmup_query_cache` 与线上配置不一致（硬编码 `use_rerank=True`），预热的是另一条路径。

### 3.5 RAG 检索流程

**优点**
- 阶段划分清晰（classify → plan → decompose → recall → dedup → rerank → hyde → expand），且**每阶段有独立的可观测接口**（`on_stage` / `stage_ms` / `emit_retrieve_summary`）。
- **门禁有「反静默回退」自检**（`_assert_route_preconditions`），实测抓到过真实故障。
- **有零成本验证手段**：`candidate_trace`（逐层归因）、`stage_trace`（接口一致性）、TEI 直探。

**缺点**
- **E1**：TEI 单点依赖且不稳定，而它同时承载 embedding 与 rerank ⇒ 宕机时**真实路由整体降级**，且降级是静默的（只有 warning）。
- **E3**：门禁自建索引 ⇒ **看不到生产索引陈旧**；本轮正是靠「抽查 chunk 内容」才发现。
- **E4**：兜底吞异常使故障表现为「某阶段没执行」，而不是报错。
- **E6**：基线维护纪律缺失曾导致 5 条路由报假退化。

---

## 4. 零成本可做 vs 需等 TEI

| 可零成本做（现在就能做） | 需 TEI 恢复 |
|---|---|
| BM25 词法路径的一切测量（R1 类） | L1/L2/L3 的**真实**召回条数与命中（R2） |
| 路由构成、权重、阈值、K 的**结构性算术**（S1/S2/R3/R4） | `rerank()` 的 `top_n` 漏斗在各层级的实际截断点（P1） |
| 假 embedding 路由的门禁（**但结论不可外推**） | 纯代码 chunk 的 rerank 分数（P2） |
| `candidate_trace` 的**逐层归因**（用假 embedding） | 真实路由上的 A/B |
| 引用溯源一致性检查（Q2，纯文本比对） | `real/on`、`real/off`、`real/disabled` 三条基线 |
| 文档与代码一致性核对（E5，纯静态） | |

**结论**：**分级设计的结构性缺陷（S1/S2/R3/R4）现在就能定量**，不需要 TEI；
但**它们对最终指标的影响必须等 TEI 恢复后才能确认**——按仓库纪律，
假路由上的结论不可外推。

---

## 5. 一句话

**分级本身是对的（按复杂度分配算力），但三条"分级 × 全局常数"的耦合没有被校准**：
阈值按全表最大权重标定（S1）、RRF 的 K 随路由数漂移（R3）、
以及一条对 124 类术语恒 0 命中的词法路由在每个层级都在跑（R1）。
**L1 是三者叠加后最脆弱的一层**：召回面最薄、阈值相对最严、且没有重排兜底。
