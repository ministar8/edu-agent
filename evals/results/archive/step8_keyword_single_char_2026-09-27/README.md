## 1. 缺陷

DS 词表里有 **4 个单字项**：`栈` / `串` / `树` / `图`。
而 `_contains_collection_keyword` 对非 ASCII 走的是 **`key in text`（子串匹配）**
⇒ 单字项会**作为子串**误命中：

| 查询 | 误命中词 | 实际归属 |
|---|---|---|
| `位示图法是怎么工作的？` | `图` → data_structure | **operating_system** |
| `资源分配图化简`（黄金集） | `图` → data_structure | operating_system |
| `IPv4 点分十进制字符串转换为…`（黄金集） | `串` → data_structure | computer_network |

## 2. 修法

| 改动 | 内容 |
|---|---|
| **收窄 DS 的 `图`** | → `图的` / `图论` / `无向图` / `有向图` / `邻接表`（覆盖不变、误命中消失） |
| **收窄 DS 的 `串`** | → `主串` / `子串` / `字符串匹配` |
| **OS 补 `位示图`** | 空闲空间管理四方法里语义无歧义的一个（`空闲` 太宽，CO 的磁盘容量题也含它，不收） |
| **`栈` / `树` 保持不变** | 经**全量黄金集核查**无同类误命中（`树` 9 条、`栈` 2 条全部命中正确学科） |

## 3. 推断 A/B（`infer_ab.log`，纯函数、不需要索引）

两个判据：① 期望集合**是否在检索范围内**（✗→✓ = 修好可达性）；
② **多余的集合**是否被剔除（噪声↓ ⇒ `category_precision` ↑）。

| 情形 | 期望在范围（前→后） | 多余集合（前→后） |
|---|---|---|
| **`#19` 位示图（**刻意不含「磁盘」**）** | **✗ → ✓** | **`['data_structure']` → `[]`** |
| 位示图 + 磁盘（对照） | ✓ → ✓ | `['data_structure','computer_organization']` → `['computer_organization']` |
| 黄金集·资源分配图 | ✓ → ✓ | `['data_structure']` → `[]` |
| 黄金集·IPv4 字符串 | ✓ → ✓ | `['data_structure']` → `[]` |
| 黄金集·KMP 主串 / 图的遍历 / 邻接表 / 邻接矩阵 / 二叉树 / 栈 | ✓ → ✓ | `[]` → `[]`（**DS 覆盖不变**） |
| `#9` 磁盘空闲空间 / `#18` 生产者-消费者 | ✓ → ✓ | 不变 |

⇒ 可达性修好 1 例（`#19`）、噪声剔除 3 例、**DS 覆盖零损失**。

## 4. ★ 探针设计的一条教训：查询里**不能带「磁盘」**

`#19` 最初写成「位示图法是怎么管理**磁盘**空闲空间的？」—— 结果**测不到这个缺陷**：
C1（Step 4）已把 `磁盘` 收进 OS 词表，所以 OS **本来就在检索范围内**，
`位示图` 的误判只表现为「多搜了 DS」而不是「搜不到 OS」。

改成**不含「磁盘」**的「位示图法是怎么工作的？」后，A/B 才显示 ✗ → ✓。
⇒ **设计探针时必须先确认「去掉待验证的那个词，缺陷是否仍然暴露」**，
否则会做出一个恒绿的探针。
