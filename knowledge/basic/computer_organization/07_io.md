## 学习目标

- 理解 I/O 接口的缓冲与控制角色
- 理解程序查询/中断/DMA 的数据传送思想

## I/O 接口

> section_id: basic-co-io-interface
> kp_ids: [co.io.interface]
> primary_kp: co.io.interface

**定义**：连接主机与外设的电路与逻辑，含数据缓冲、状态与命令。

**为什么**：主机与设备速度、时序、电气特性不同，不能直连。

**思想**：接口是**时序与速率的适配层**。

---

## 程序中断方式

> section_id: basic-co-io-interrupt_io
> kp_ids: [co.io.interrupt_io]
> primary_kp: co.io.interrupt_io

**定义**：外设就绪或完成时向 CPU 发中断；CPU 响应后用程序传送数据。

**为什么**：相对轮询，减少 CPU 空转等待。

**机制**：中断请求→判优→响应→保存现场→服务→返回。

**思想**：用**事件驱动**代替忙等。

---

## DMA 方式

> section_id: basic-co-io-dma
> kp_ids: [co.io.dma]
> primary_kp: co.io.dma

**定义**：DMA 控制器在外设与主存间直接传送成块数据，占用总线但几乎不打扰 CPU。

**为什么**：高速成块传送用程序逐字搬运太慢。

**机制**：传送前给计数与地址；传送中抢用总线；结束发中断。

**思想**：**专用控制器接管批量数据路径**；CPU 从搬运工变成发令者。

---

## 通道与其他方式

> section_id: basic-co-io-channel
> kp_ids: [co.io.channel]
> primary_kp: co.io.channel

**定义**：更独立的 I/O 处理器，能执行通道程序，管理多设备。

**思想**：I/O 自治程度逐步提高——程序查询 → 中断 → DMA → 通道；CPU 干预越来越少。

---

## I/O 系统的组成

> section_id: basic-co-io-system
> kp_ids: [co.io]

**I/O 系统**由 I/O 软件与 I/O 硬件构成。

- **I/O 硬件**：I/O 设备（外部设备）、I/O 接口（又称 I/O 控制器、设备控制器）、I/O 总线。
- **I/O 软件**：驱动程序、用户程序、管理程序等。

**主机与外设之间的路径**：CPU/主存 → I/O 总线 → I/O 接口 → 通信总线 → 外设。

**I/O 指令**：CPU 指令的一部分，由操作码、命令码、设备码组成，分别标识 I/O 指令、操作类型与目标设备。

**通道指令**：通道能识别的指令。通道程序提前编制好放在主存中，CPU 执行 I/O 指令对通道发出命令，由通道执行通道指令代替 CPU 管理设备。

---

## I/O 接口的功能与端口编址

> section_id: basic-co-io-port
> kp_ids: [co.io.interface]

**I/O 接口的作用**：数据缓冲（匹配主机与外设速度）、错误或状态监测、控制与定时、数据格式转换（串/并转换）、与主机和设备通信。

**结构**：面向主机一侧为**内部接口**（与系统总线相连），面向设备一侧为**外部接口**（经电缆连外设，可能为串行，需串/并转换）。

**I/O 端口**：接口电路中可被 CPU 直接访问的**寄存器**。

- **数据端口（数据寄存器）**：可读可写。
- **控制端口（控制寄存器）**：只能写。
- **状态端口（状态寄存器）**：只能读。

**两种编址方式**：

| 维度 | 统一编址（存储器映射） | 独立编址（I/O 映射） |
|---|---|---|
| 区分方式 | 靠不同地址码 | 靠不同指令 |
| 访问指令 | 统一的访存指令 | 专门的 I/O 指令 |
| 优点 | 编程灵活、端口空间大、控制逻辑简单 | 程序清晰、地址位数少、不占主存空间 |
| 缺点 | 占用主存地址空间、译码慢 | I/O 指令类型少、需两组控制信号 |

**分类**：按数据传送方式分并行接口与串行接口；按控制方式分程序查询接口、中断接口、DMA 接口；按灵活性分可编程接口与不可编程接口。

## 程序查询方式

> section_id: basic-co-io-polling
> kp_ids: [co.io.interface]

**定义**：CPU 不断轮询 I/O 控制器的**状态寄存器**，检测到「已完成」后从**数据寄存器**取出数据。CPU 与外设串行工作，需忙等，效率低。

**优点**：接口设计简单，设备量少。

**缺点**：CPU 花费大量时间查询与等待；若独占查询，一段时间内只能与一台外设交换信息。

**两种分类**：

- **独占查询**：CPU 全部时间都在查询 I/O 状态，完全串行。
- **定时查询**：每隔一段时间查询一次 I/O 状态，查询间隔内 CPU 可执行其它程序。

## 中断系统与中断处理

> section_id: basic-co-io-interrupt_flow
> kp_ids: [co.io.interrupt_io]

**中断**：CPU 执行现行程序时出现急需处理的异常或特殊请求，CPU 暂停现行程序转去处理，处理完毕后自动返回断点继续执行。

**工作流程**：

1. **中断请求**：中断源通过数据线向 CPU 发中断请求信号，用中断请求标记触发器暂存（CPU 无法即时处理请求）。外中断时，CPU 在每条指令执行阶段结束前统一发出中断查询信号。
2. **中断响应**：需满足中断源有请求、CPU 开中断、一条指令已执行完毕且无更紧迫任务。多个中断源同时请求时由判优逻辑（硬件排队器或软件查询程序）选定响应对象。
3. **中断处理**：
   - **中断隐指令**（硬件自动完成）：关中断、保存断点（PC 与 PSW）、引出中断服务程序。
   - **中断服务程序**：保护现场（保存通用寄存器与状态寄存器）、执行中断服务、恢复现场。

**向量中断与中断向量**：

- **中断向量**：由硬件产生的中断服务程序入口地址。
- **中断向量表**：所有中断向量构成的表。
- **中断向量地址**：中断向量表中每个表项所在的内存地址，即中断服务程序入口地址的地址。CPU 检测到中断后查询中断向量表以找到中断处理程序。

**单重中断与多重中断**：单重中断在执行中断服务程序时不响应新中断；多重中断（中断嵌套）允许响应新中断。**中断屏蔽技术**用于多重中断——每个中断源有一个屏蔽触发器，组合成屏蔽字寄存器；屏蔽字中 1 的个数越多、优先级越高，对角线一定为 1（至少能屏蔽自身）。

**中断判优优先级思想**：硬件故障最高，其次软件中断；非屏蔽优于可屏蔽；DMA 请求优于 I/O 中断请求；高速设备优于低速设备；输入优于输出；实时设备优于普通设备。

## DMA 的三种传送方式

> section_id: basic-co-io-dma_transfer
> kp_ids: [co.io.dma]

**定义**：DMA 控制器与 CPU 共享主存时的三种传送方式，用于解决 DMA 与 CPU 的访存冲突。

| 方式 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| 停止 CPU 访存 | DMA 传送时 CPU 完全放弃主存使用权，暂停 CPU | 控制简单，适合高速设备成组传送 | CPU 利用率低，主存利用率低 |
| 周期窃取（周期挪用） | DMA 需要时窃取一个或几个主存周期（CPU 暂停一个存取周期） | CPU 工作与 DMA 传送并行，利用率高 | 每次传送都要申请、占用、释放总线，传输率不如前者 |
| DMA 与 CPU 交替访存 | 把一个 CPU 存取周期分为两个子周期，一个供 DMA、一个供 CPU | 传送速率高，CPU 不停止运行 | 需主存在一个存取周期内完成两次读写，硬件逻辑复杂 |

**特点**：只有具有 DMA 接口的外部设备才能发出 DMA 请求；传送期间总线控制权由 DMA 控制器掌握；CPU 只在开始与结束时干预；传送结束后由中断服务程序完成处理。

## 通道的类型

> section_id: basic-co-io-channel_type
> kp_ids: [co.io.channel]

**定义**：I/O 通道是 DMA 方式的发展，是专门负责 I/O 操作的硬件，可独立执行通道程序。

**三种通道类型**：

- **字节多路通道**：以字节为单位交叉为多个慢速设备服务，每个设备占一个字节的时间片轮转服务，适合连接大量低速设备。
- **数组多路通道**：以数据块为单位交替为多个高速设备服务，一个设备传送一个数据块后切换到下一个设备，适合连接中速设备。
- **选择通道**：一次只选择一个设备，传送期间独占通道，以数据块为单位传送，传输率最高但设备等待时间长，适合连接高速设备。

**通道工作流程**：CPU 遇到 I/O 指令 → 组织通道程序并启动通道 → 通道从主存取出并执行通道指令 → 完成后向 CPU 发中断请求 → CPU 响应中断做后续处理。

## I/O 设备与显示存储器

> section_id: basic-co-io-device
> kp_ids: []

**外部设备**（外围设备）：除主机外能直接或间接与计算机交换信息的装置。输入设备如键盘、鼠标；输出设备如显示器、打印机。

**显示器分类**：按器件分阴极射线管（CRT）、液晶（LCD）、LED 显示器；按显示内容分字符显示器、图形显示器、图像显示器；按扫描方式分光栅扫描与随机扫描。

**显示器参数**：

- **屏幕大小**：以对角线长度表示。
- **分辨率**：能表示的像素个数，以宽×高表示。
- **灰度级**：像素亮暗差别（彩色时为颜色差别），n 位可表示 2ⁿ 种亮度或颜色。
- **刷新率**：单位时间扫描整个屏幕的次数，通常 60~120 Hz。

**显示存储器（VRAM）**：也称刷新存储器，存储一帧图像信息。

    VRAM 容量 = 分辨率 × 灰度级位数（一帧大小即显存理论最小值）
    VRAM 带宽 = 分辨率 × 灰度级位数 × 帧频（B/s）

**打印机**：按印字原理分击打式（成本低、防伪性好，但噪声大、速度慢）与非击打式（速度快、噪声小，但成本高）；按工作方式分串行打印机与行式打印机；按实现分针式、喷墨式、激光打印机。

## SPOOLing 技术（假脱机）

> section_id: basic-co-io-spooling
> kp_ids: []

**定义**：SPOOLing（同时外设联机操作），又称假脱机技术，是把独占设备改造为共享设备的一种技术。

**核心思想**：用软件方式模拟脱机输入/输出，在主机上设置输入井和输出井（磁盘上的缓冲区）。

**组成**：输入井与输出井（磁盘存储区，模拟磁带）、输入/输出缓冲区（内存缓冲区）、输入进程与输出进程（模拟外围控制机）。

**工作过程**：输入时输入进程把设备数据经缓冲区送入输入井，CPU 需要时从输入井读取；输出时 CPU 把数据送入输出井，输出进程把数据经缓冲区送到设备。

**特点**：提高了 I/O 速度（实际操作面向磁盘井区）、把独占设备改造为共享设备、实现了虚拟设备功能。

**典型应用**：共享打印机——多个进程的打印请求先送入输出井排队，输出进程依次取出打印。
