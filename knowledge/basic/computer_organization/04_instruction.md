## 学习目标

- 理解指令格式与寻址方式
- 理解 ISA 的软件/硬件边界
- 理解 RISC 与 CISC 的设计取向

---

## 指令格式

> section_id: basic-co-instruction-format
> kp_ids: [co.instruction.format]
> primary_kp: co.instruction.format

**定义**：指令由操作码与地址码（及扩展字段）构成，规定「做什么」与「操作数在哪」。

**为什么**：操作种类与寻址能力要在「指令长度 / 灵活性 / 译码成本」间平衡。

**思想**：定长利于译码流水；变长利于编码密度——格式是机器语言与硬件的契约。

---

## 寻址方式

> section_id: basic-co-instruction-addressing
> kp_ids: [co.instruction.addressing]
> primary_kp: co.instruction.addressing

**定义**：形成操作数有效地址的方式（立即、直接、间接、寄存器、偏移、变址等）。

**为什么**：同一算法在不同数据布局下需要不同的地址形成路径。

**思想**：寻址是**地址计算的语义**；有效地址 ≠ 物理地址（若有虚拟存储）。

## ISA 与 RISC/CISC

> section_id: basic-co-instruction-isa
> kp_ids: [co.instruction.isa, co.instruction.risc_cisc]
> primary_kp: co.instruction.isa

**ISA**

**定义**：指令集体系结构——软件可见的指令、寄存器、数据类型、存储模型等契约。

**为什么**：是软件与硬件的分界面；同一 ISA 可有不同微结构实现。

**RISC / CISC**

**思想**：

- CISC：指令功能强、格式多、面向编译器简化
- RISC：指令规整、Load/Store 型、利于流水与优化

**特点**：取向不同，不能简单说「谁更快」；现代 CPU 常在 ISA 层做减法、在微结构层做加法。

## 指令的地址码与地址数

> section_id: basic-co-instruction-address_count
> kp_ids: [co.instruction.format]

**定义**：一条指令由**操作码**与**地址码**组成，操作码规定做什么，地址码给出操作数所在位置或下一条指令地址。按地址码个数分为：

| 类型 | 形式 | 含义 |
|---|---|---|
| 零地址 | OP | 不需要操作数（如空操作、停机），或操作数隐含在栈顶 |
| 一地址 | OP A1 | 单操作数，或一个操作数隐含在累加器中 |
| 二地址 | OP A1 A2 | (A1) OP (A2) → A1，最常用 |
| 三地址 | OP A1 A2 A3 | (A1) OP (A2) → A3，结果另存 |
| 四地址 | OP A1 A2 A3 A4 | 再显式给出下一条指令地址 |

**特点**：指令总长度固定时，地址码数量越多，单个地址的位数越少，寻址能力越弱。

## 指令字长与操作码结构

> section_id: basic-co-instruction-wordlength_opcode
> kp_ids: [co.instruction.format]

**按指令字长分**：半字长指令、单字长指令、双字长指令。

- **定长指令字结构**：所有指令长度相等，便于译码与流水。
- **变长指令字结构**：各指令长度不等，编码密度高但译码复杂。

**按操作码长度分**：

- **定长操作码**：所有指令操作码长度相同；n 位操作码最多支持 2ⁿ 条指令，译码简单但灵活性低。
- **可变长操作码**：各指令操作码长度可变，译码复杂但灵活。
- **扩展操作码**：指令总长度不变，不同地址数的指令使用不同长度的操作码。

**扩展操作码的设计约束**：

- 不允许短操作码是长操作码的前缀（否则译码产生歧义）。
- 各指令的操作码不能重复。

**思想**：对使用频率高的指令分配较短的操作码，可在固定字长下容纳更多指令、减少译码时间。

## 指令的操作类型

> section_id: basic-co-instruction-op_type
> kp_ids: [co.instruction.isa]

**四类操作**：

1. **数据传送类**：如 LOAD（存储器→寄存器）、STORE（寄存器→存储器）。
2. **算术逻辑类**：加减乘除、增 1 减 1、求补、浮点运算；与或非、异或、位操作等；以及算术移位、逻辑移位、循环移位。
3. **程序控制类**：改变程序执行流，如无条件转移、条件转移、调用与返回、陷阱指令，均会改变程序计数器的值。
4. **输入输出类**：实现 CPU 寄存器与 I/O 端口之间的数据传送。

## 指令寻址：顺序与跳跃

> section_id: basic-co-instruction-instruction_addressing
> kp_ids: [co.instruction.addressing]

**定义**：指令寻址确定下一条指令的存放地址，由程序计数器 PC 指明。

- **顺序寻址**：(PC) + 「1」→ PC。此处「1」指一个指令字长，实际加值因指令长度与编址方式而异（按字节编址时按指令字节数自增）。
- **跳跃寻址**：由转移指令给出下一条指令的地址。

**思想**：顺序寻址是默认路径，跳跃寻址用于分支与循环；变长指令与按字节编址时，PC 自增值需由指令长度决定。

## 数据寻址与有效地址

> section_id: basic-co-instruction-data_addressing
> kp_ids: [co.instruction.addressing]

**定义**：数据寻址确定本条指令地址码所指明的操作数**有效地址 EA**。因地址码给出的形式地址 A 不一定就是真实地址，需按寻址方式解读。

**常见寻址方式的 EA 公式**：

| 寻址方式 | 有效地址 | 访存次数（不含取指） |
|---|---|---|
| 立即寻址 | A 即操作数本身 | 0 |
| 直接寻址 | EA = A | 1 |
| 间接寻址 | EA = (A) | 2 起（多次间接更多） |
| 寄存器寻址 | EA = R | 0 |
| 寄存器间接寻址 | EA = (R) | 1 |
| 隐含寻址 | 操作数地址隐含于指令 | 视实现而定 |
| 基址寻址 | EA = (BR) + A | 1 |
| 变址寻址 | EA = (IX) + A | 1 |
| 相对寻址 | EA = (PC) + A | 1 |

**基址寻址与变址寻址的对比**：

| 维度 | 基址寻址 | 变址寻址 |
|---|---|---|
| 基址寄存器内容 | 程序执行中不变（面向操作系统） | 可由用户改变（面向用户） |
| 形式地址 | 作偏移量 | 作基地址 |
| 主要用途 | 扩大寻址范围、支持程序浮动 | 数组处理、编制循环程序 |

**相对寻址**：以 PC 所指地址为起点，A 为可正可负的偏移量（补码表示），操作数地址随 PC 变化而保持与指令的固定间隔，便于程序浮动，常用于转移指令。

**堆栈寻址**：操作数存放在堆栈中，隐含使用堆栈指针 SP。堆栈按后进先出（LIFO）管理。**硬堆栈**用寄存器实现，压入弹出无需访存、速度快但成本高；**软堆栈**在主存中划分区域，需访存、速度慢但成本低。

## 机器级代码与汇编

> section_id: basic-co-instruction-assembly
> kp_ids: [co.instruction.isa]

**定义**：汇编语言与机器语言都是**机器级代码**，二者一一对应；高级语言与机器级代码不直接对应。

**思想**：一条机器指令对应一条汇编语句；高级语言经编译→汇编→链接得到目标代码。汇编语言与具体机器相关，没有通用性。

**格式**：AT&T 格式常用于 Unix/Linux，Intel 格式常用于 Windows；两种格式的源操作数与目的操作数书写顺序不同。

**栈帧**：函数调用时保存局部变量与调用相关信息的内存区域。栈底由基址指针 EBP 指向、栈顶由栈顶指针 ESP 指向；返回地址、上一层栈帧基址、局部变量、调用参数都在栈帧中。参数与返回值通过寄存器（如 EAX）及栈传递。
