## I/O 软件层次

> section_id: basic-os-io-software
> kp_ids: [os.io.software]
> primary_kp: os.io.software

**思想**：自底向上——中断处理、设备驱动、与设备无关的软件、用户层。

**为什么**：把硬件差异关在驱动层，上层统一抽象（打开/读写/关闭）。

## 缓冲管理

> section_id: basic-os-io-buffer
> kp_ids: [os.io.buffer]
> primary_kp: os.io.buffer

**定义**：在 CPU 与设备之间设置暂存区。

**为什么**：匹配速度差异；减少等待与中断次数。

**机制**：单缓冲、双缓冲、循环缓冲——双缓冲可让处理与传输重叠。

**思想**：**缓冲换并行与平稳**；过多缓冲增加延迟与内存占用。

---

## 设备管理

> section_id: basic-os-io-device
> kp_ids: [os.io.device]
> primary_kp: os.io.device

**问题**：分配、控制、回收设备资源。

**思想**：设备独立性（逻辑设备名→物理设备）；SPOOLing 把独占设备虚拟成共享（如打印机）。

## 设备分类

> section_id: basic-os-io-device_class
> kp_ids: [os.io.device]
> primary_kp: os.io.device

**按使用特性**：人机交互类（速度慢，如鼠标键盘）、存储设备（速度快，如磁盘）、网络通信设备（速度居中）。

**按传输速率**：低速、中速、高速设备。

**按信息交换单位**：

- **块设备**：以**块**为单位传输，可寻址、可随机读写，如磁盘，多采用 DMA。
- **字符设备**：以**字符**为单位传输，不可寻址，多采用中断驱动，如键盘。

## I/O 控制器

> section_id: basic-os-io-controller
> kp_ids: [os.io.device]
> primary_kp: os.io.device

**定义**：I/O 控制器（设备控制器）是 CPU 与设备机械部件之间的中介，CPU 通过它来控制设备。

**功能**：接收并识别 CPU 的命令（控制寄存器）、向 CPU 报告设备状态（状态寄存器）、进行数据交换（数据寄存器）、地址识别（区分各寄存器）。

**编址方式**：

- **内存映像 I/O**：控制器寄存器占用内存地址，可用访存指令直接访问，简化指令。
- **独立编址**：控制器寄存器有独立的 I/O 地址，需要专门的 I/O 指令。

一个控制器可对应多个设备，且数据/控制/状态寄存器可能各有多个。

---

## I/O 控制方式的对比

> section_id: basic-os-io-control_mode
> kp_ids: [os.io.device]
> primary_kp: os.io.device

| 方式 | 传送单位 | 数据流向 | CPU 干预 | 特点 |
|---|---|---|---|---|
| 程序直接控制 | 字 | 设备 ↔ CPU ↔ 内存 | 极频繁，轮询忙等 | 简单，但 CPU 利用率低 |
| 中断驱动 | 字 | 设备 ↔ CPU ↔ 内存 | 每个字开始/结束 | 可并行，但中断频繁 |
| DMA | 块 | 设备 ↔ 内存（不经 CPU） | 每个数据块开始/结束 | 效率高，多用于块设备 |
| 通道控制 | 一组块 | 设备 ↔ 内存 | 极低 | CPU、通道、设备可并行 |

**思想**：控制方式演进的共同方向，是逐步把 CPU 从逐字、逐块的搬运工作中解放出来，让 CPU、控制器与设备尽可能并行。

## 设备独立性与逻辑设备表

> section_id: basic-os-io-independence
> kp_ids: [os.io.device]
> primary_kp: os.io.device

**设备独立性**：操作系统把所有外部设备统一当作**特殊文件**看待，用户像使用文件一样操纵设备，无须了解其具体存在形式。

**好处**：方便用户操作、易于实现 I/O 重定向；程序运行不受具体机器影响；提高设备利用率与分配灵活性；提高系统的可适应性与可扩展性。

**设备独立性软件的主要功能**：提供统一的调用接口、设备保护、差错处理、设备的分配与回收、数据缓冲区管理，以及建立**逻辑设备名到物理设备名**的映射并据此选择驱动程序。

**逻辑设备表（LUT）**：记录逻辑设备名与物理设备名及驱动程序入口的对应关系。可全系统一张（逻辑设备名不可重复，适合单用户），也可每用户一张（逻辑设备名可重复，适合多用户）。

## 缓冲的类型与时间开销

> section_id: basic-os-io-buffer_type
> kp_ids: [os.io.buffer]
> primary_kp: os.io.buffer

**作用**：缓和 CPU 与 I/O 设备的速度矛盾、减少中断频率、解决数据粒度不匹配、提高二者的并行性。

**类型**：单缓冲、双缓冲、循环缓冲、缓冲池（含空缓冲队列、输入队列、输出队列，以及四类工作缓冲区 hin/sin/hout/sout）。

**单缓冲**：处理一块数据的平均时间为 **Max(C, T) + M**。
**双缓冲**：处理一块数据的平均时间为 **Max(C + M, T)**。

其中 T 为设备把数据输入缓冲区的时间，M 为缓冲区把数据送入工作区的时间，C 为 CPU 处理一块数据的时间。

**思想**：缓冲用「额外的一份存储」换取传输与处理的**重叠**；双缓冲让处理与传输更加并行，缓冲池则把缓冲变为可被多个并发进程共用的公共资源。

## 假脱机技术与设备分配

> section_id: basic-os-io-spooling
> kp_ids: [os.io.device]
> primary_kp: os.io.device

**假脱机（SPOOLing）技术**：用软件方式模拟脱机输入/输出，需要多道程序设计技术支持，本质是**以空间换时间**。

**组成**：磁盘上的**输入井/输出井**（模拟脱机磁带）、**输入/输出进程**（模拟外围控制机）、内存中的**输入/输出缓冲区**；由预输入程序、井管理程序、缓输出程序管理。不需要额外的外围计算机。

**共享打印机**：独占设备经 SPOOLing 在逻辑上变为可共享设备。进程的打印请求被转化为在输出井中申请存储区并挂入假脱机文件队列，进程因而感到自己独占了打印机。

**设备分配**：

- **固有属性**：独占设备、共享设备、虚拟设备。
- **分配算法**：先来先服务、优先级高者优先、短任务优先。
- **安全性**：安全分配方式（分配后即使进程阻塞，一个时段只用一个设备，不会死锁）与不安全分配方式（进程可同时持有多个设备，可能死锁）。

**数据结构**：设备控制表 DCT、控制器控制表 COCT、通道控制表 CHCT、系统设备表 SDT。分配时按设备 → 控制器 → 通道逐级检查，三者均分配成功才算分配成功。

## 通信方式：单工、半双工与全双工

> section_id: basic-os-io-comm_mode
> kp_ids: []

**单工**：信号只能沿一个方向传输，任何时候不能反向。
**半双工**：允许双向传输，但某一时刻只能单向，是可切换方向的单工。
**全双工**：允许同时双向传输，需两个信道，收发双方都有独立的收发能力。

**与缓冲的关系**：两台机器各设单缓冲区时，同一时刻只能单向传输；各设接收与发送双缓冲区时，同一时刻可双向传输。

## I/O 接口与设备接口类型

> section_id: basic-os-io-interface
> kp_ids: []

**定义**：I/O 接口（设备接口）是设备与主机之间的交界，向上呈现一组可供 CPU 访问的寄存器（数据、控制、状态），向下连接设备的具体机械与电子部件。

**接口类型**：

- **字符设备接口**：以字符为单位逐个传输，不可寻址，通常只支持顺序访问，如键盘、打印机；多采用中断驱动方式。
- **块设备接口**：以块为单位传输，可寻址、可随机读写，如磁盘；上层多以「读/写若干块」的形式发起请求，并常借助 DMA 完成传输。
- **网络接口**：面向数据包的收发，没有「块地址」的概念，也不适合用统一的文件语义描述；其数据流的速率与到达时机都不确定。

**思想**：接口把各类设备的差异收敛为少数几种统一的访问模式，使上层软件能用相近的方式操纵形态迥异的设备。

## 阻塞 I/O 与非阻塞 I/O

> section_id: basic-os-io-blocking
> kp_ids: []

**定义**：阻塞与非阻塞描述进程发起 I/O 请求之后，是否因等待 I/O 完成而暂停自身执行。

**区别**：

- **阻塞 I/O**：进程发出请求后进入等待状态，直到数据就绪并完成传输才被唤醒。编程模型简单、贴合顺序思维，但进程在等待期间不能推进其他工作。
- **非阻塞 I/O**：进程发出请求后立即返回，若数据尚未就绪则得到「未就绪」的反馈，进程可继续执行其他逻辑，稍后再询问或等待通知后取用数据。进程不被挂起，但需要额外处理「未就绪」与重试，逻辑更复杂。

**思想**：二者是在「编程简单」与「CPU 及设备的利用率」之间的取舍；若把等待交由其他机制（如多路复用、异步通知）承接，进程便可在同一时段推进多项工作。

## I/O 调度

> section_id: basic-os-io-schedule
> kp_ids: []

**定义**：I/O 调度是在多个待处理的 I/O 请求之间确定服务顺序的机制。

**机制**：请求到达后先进入队列，调度程序按某种次序选出下一个服务的请求；若相邻请求落在设备上相近的位置，可**合并**为一个请求，以减少寻道与额外开销。

**目标**：提高设备吞吐量、缩短平均等待时间，并在多个进程之间公平地分配设备使用权。常见的次序思路有先来先服务、最短寻道优先等。

**思想**：I/O 调度的价值来自**请求排队与合并**——把大量零散的请求整理成更有秩序的序列，从而以较少的设备移动完成更多的传输。
