## 进程与线程

> section_id: basic-os-process-thread
> kp_ids: [os.process.thread]
> primary_kp: os.process.thread

**定义**：进程是资源分配与执行的基本实体（有独立地址空间）；线程是 CPU 调度的轻量执行流。

**为什么**：把「资源拥有」与「执行调度」拆开，提高并发粒度与切换效率。

## 进程状态与转换

> section_id: basic-os-process-state
> kp_ids: [os.process.state]
> primary_kp: os.process.state

**基本状态**：就绪、运行、阻塞（等待）。

**机制**：调度选中→运行；时间片完→就绪；等待事件→阻塞；事件完成→就绪。

**思想**：状态机刻画「能否立刻运行」与「在等什么」。

## 进程同步

> section_id: basic-os-process-sync
> kp_ids: [os.process.sync]
> primary_kp: os.process.sync

**问题**：并发执行时对共享资源的访问要保持正确次序与互斥。

**为什么**：交错执行可能导致「与预期序列不一致」的结果（竞态）。

**机制思想**：互斥（临界区）与同步（前驱关系）是两个相关但不同的约束。

## 信号量与 PV

> section_id: basic-os-process-semaphore
> kp_ids: [os.process.semaphore, os.process.pv]
> primary_kp: os.process.semaphore

**定义**：信号量为可增减的整型量，配合 P（wait）/ V（signal）操作。

**思想**：用**计数与阻塞队列**表达资源可用量与等待关系；P 申请、V 释放。

**机制**：P 减到负则等待；V 唤醒等待者——互斥与同步都可由此编码。

## 管程与经典同步问题

> section_id: basic-os-process-monitor
> kp_ids: [os.process.monitor, os.process.classic_sync]
> primary_kp: os.process.classic_sync

**管程**：把共享数据与操作封装为带条件等待的临界对象，降低信号量误用。

**经典问题**：生产者消费者、哲学家进餐、读者写者——用有限缓冲、资源分配、读写并发等模型表达同步约束。

**思想**：同步问题的本质是**不变式 + 等待/唤醒规则**，工具只是表达方式。

## 死锁

> section_id: basic-os-process-deadlock
> kp_ids: [os.process.deadlock]
> primary_kp: os.process.deadlock

**定义**：一组进程互相持有对方所需资源并循环等待，都无法推进。

**成因**：互斥、占有并等待、不可剥夺、循环等待（必要条件）。

**处理思想**：预防（破坏条件）、避免（分配前判断安全）、检测+恢复、鸵鸟（忽略）。

## 银行家算法

> section_id: basic-os-process-bankers
> kp_ids: [os.process.bankers]
> primary_kp: os.process.bankers

**基本思想**：分配前试探「是否存在安全序列」，仅在安全时分配。

**为什么**：在允许互斥与等待的同时，避免进入不安全（可能死锁）状态。

**机制**：工作向量模拟可回收资源；能完成所有进程则安全。

## 进程的构成与特征

> section_id: basic-os-process-entity
> kp_ids: [os.process.thread]
> primary_kp: os.process.thread

**进程实体（进程映像）**：由 **PCB**、**程序段**、**数据段**三部分组成，是进程在某一时刻的静态快照。其中 PCB 是进程存在的**唯一标志**——创建进程即创建 PCB，撤销进程即撤销 PCB。

**PCB 的主要内容**：进程标识（PID、UID）、处理机状态（通用寄存器、PC、PSW 等现场信息）、进程调度信息（状态、优先级）、资源清单、进程控制信息。

**特征**：

- **动态性**（最基本）：进程是程序的一次执行过程，有产生、变化与消亡。
- **并发性**：多个进程实体可在一段时间内并发推进。
- **独立性**：进程是能独立运行、独立获得资源、独立接受调度的基本单位。
- **异步性**：各进程以独立的、不可预知的速度推进。
- **结构性**：每个进程都配有 PCB。

**顺序执行与并发执行**：顺序执行具有**顺序性、封闭性、可再现性**；并发执行则表现为**间断性、失去封闭性、不可再现性**。

## 进程控制

> section_id: basic-os-process-control
> kp_ids: [os.process.state]
> primary_kp: os.process.state

**思想**：进程控制即实现进程状态转换，由**原语**完成。原语具有**原子性**，常借助关中断/开中断实现。

- **创建**：申请空白 PCB → 分配资源 → 初始化 PCB → 插入就绪队列。
- **终止**：按 PID 找到 PCB → 若在运行则终止执行 → 终止其子进程 → 归还资源 → 撤销 PCB。
- **阻塞与唤醒**：成对出现。阻塞是进程**主动**的行为（请求资源失败或等待事件），唤醒是**被动**的（由其他进程在事件完成时触发）。
- **切换**：保存当前进程现场到其 PCB → 移入相应队列 → 选择新进程 → 由新进程 PCB 恢复现场。

**上下文**：进程上下文指 CPU 寄存器值、进程状态、堆栈内容等运行环境；进程切换必然发生在内核态。

## 进程间通信

> section_id: basic-os-process-ipc
> kp_ids: []

**前提**：一个进程不允许直接访问另一个进程的地址空间，必须经内核提供的机制交换数据。

**方式**：

- **共享存储器**：两进程映射同一块共享空间，访问需互斥。基于数据结构共享为低级方式（受限、慢）；基于存储区共享为高级方式（自由、快）。
- **管道通信**：管道是特殊的共享文件（内存中固定大小的缓冲区）。半双工，读写需互斥；写满则写进程阻塞，读空则读进程阻塞；数据被读出后即消失。
- **消息传递**：以格式化的消息为单位，经发送/接收原语交换。分**直接通信**（直接发往目标进程）与**间接通信**（经信箱中转）。

## 线程的实现方式与多线程模型

> section_id: basic-os-process-thread_impl
> kp_ids: [os.process.thread]
> primary_kp: os.process.thread

**线程控制块（TCB）**：每个线程有线程 ID、程序计数器、寄存器、堆栈指针、状态、优先级等。线程几乎不拥有系统资源，共享所属进程的资源，同进程内线程切换开销小。

**用户级线程（ULT）**：由线程库在用户空间管理，内核不可见。切换无须进入核心态、开销小，还可由进程定制调度算法；但一个线程阻塞会阻塞整个进程，且不能在多核上并行。

**内核级线程（KLT）**：由内核管理与调度，是处理机分配的单位。一个线程阻塞不影响其他线程，可多核并行；但切换需进入核心态，开销大。

**多线程模型**：**多对一**（多个 ULT 映射一个 KLT，开销小但并发度低）、**一对一**（一 ULT 对一 KLT，并发高但开销大）、**多对多**（折中）。

## 处理机调度的层次与时机

> section_id: basic-os-process-schedule_level
> kp_ids: [os.process.schedule]
> primary_kp: os.process.schedule

**三个层次**：

| 层次 | 发生频率 | 作用对象去向 | 对状态的影响 |
|---|---|---|---|
| 高级调度（作业调度） | 低 | 外存 → 内存（作业） | 无 → 创建态 → 就绪态 |
| 中级调度（内存调度） | 中 | 外存 ↔ 内存（进程） | 挂起态 ↔ 就绪态 |
| 低级调度（进程调度） | 高 | 内存 → CPU | 就绪态 → 运行态 |

**低级调度**是最基本的一种调度，频率最高。高级调度决定哪些作业进入内存并创建进程；中级调度在内外存之间对换挂起的进程，以提高内存利用率。

**调度时机**：进程主动放弃（终止、阻塞、请求 I/O）或被动放弃（时间片用完、更高优先级进程到达）。中断处理过程、内核程序临界区中、原语执行中不宜进行切换。

## 调度算法的评价指标

> section_id: basic-os-process-schedule_metric
> kp_ids: [os.process.schedule]
> primary_kp: os.process.schedule

**基础公式**（完成与提交按同一时间基准度量）：

- CPU 利用率 = 有效工作时间 / 总工作时间
- 系统吞吐量 = 完成的作业数 / 花费的总时间
- 周转时间 = 作业完成时间 − 作业提交时间 = 等待时间 + 运行时间
- 平均周转时间 = 各作业周转时间之和 / 作业数
- 带权周转时间 = 周转时间 / 作业实际运行时间（恒 ≥ 1）
- 响应时间：从提交请求到首次产生响应的时间
- 响应比 = (等待时间 + 要求服务时间) / 要求服务时间（恒 ≥ 1）

**思想**：调度算法主要影响**等待时间**；不同系统的目标不同——批处理追求平均周转时间与吞吐量，分时追求响应时间，实时追求截止时间。

## 常见调度算法对比

> section_id: basic-os-process-schedule_algo
> kp_ids: [os.process.schedule]
> primary_kp: os.process.schedule

| 算法 | 抢占 | 主要特点 | 主要不足 |
|---|---|---|---|
| 先来先服务 FCFS | 非抢占 | 公平、实现简单 | 对短作业不利，平均等待时间长 |
| 短作业优先 SJF | 非抢占 | 平均等待时间最短 | 对长作业不利，可能饥饿 |
| 最短剩余时间优先 SRTN | 抢占 | SJF 的抢占版本 | 长作业仍可能饥饿 |
| 高响应比优先 HRRN | 非抢占 | 兼顾等待与运行时间 | 每次需计算响应比 |
| 时间片轮转 RR | 抢占 | 公平、响应快，适合分时 | 切换开销大，不区分紧急程度 |
| 优先级调度 | 两者皆可 | 按优先级区分紧急程度 | 低优先级可能饥饿 |
| 多级反馈队列 MLFQ | 抢占 | 综合平衡，兼顾响应与周转 | 系统开销大 |

**思想**：各算法在「公平」「平均等待」「响应性」「实现开销」之间取舍，没有对一切目标都最优的单一算法。就绪队列可按优先级组织，并常让 I/O 型进程获得更高优先级。

## 临界区与互斥实现

> section_id: basic-os-process-mutex
> kp_ids: [os.process.sync]
> primary_kp: os.process.sync

**临界资源**：一段时间内只允许一个进程使用的资源；访问它的那段代码称为**临界区**。对不同的临界资源应设置不同的互斥信号量。

**临界区四条原则**：

- **空闲让进**：临界区空闲时应允许一个进程进入。
- **忙则等待**：已有进程在临界区时，其他进程须等待。
- **有限等待**：请求进入的进程应在有限时间内进入，避免「死等」。
- **让权等待**：进不去时应释放 CPU，避免「忙等」（遵循更优，但非必须）。

**实现思路**：软件方法（标志位、轮转标志等）尝试在不借助硬件的条件下构造互斥，但存在忙等；硬件方法（关中断、测试并建立、交换指令等）把「检查与上锁」变成原子操作，更简洁，但仍可能忙等。互斥锁是解决临界区最直接的工具，其加锁/解锁须原子执行。

## 信号量的类型

> section_id: basic-os-process-semaphore_type
> kp_ids: [os.process.semaphore, os.process.pv]
> primary_kp: os.process.semaphore

**信号量**是表示资源数量的整型量，配一对原语 P（wait，申请）与 V（signal，释放）使用。

- **整型信号量**：以自减/自增表示占用与释放，资源不足时陷入忙等。
- **记录型信号量**：除计数值外附带阻塞队列，资源不足时用 block 主动阻塞、释放时用 wakeup 唤醒，避免忙等。
- **AND 型信号量**：一次申请多种资源，全部满足才分配，否则整体阻塞，用于避免死锁。
- **信号量集**：在 AND 型基础上为每类资源设定最低需求量与本次申请量，适应多资源、多数量的场景。

**应用**：设初值为 1 的互斥信号量可实现**互斥**；设初值为 0 的同步信号量可实现**前驱/同步**关系。

**思想**：信号量由整型逐步演进为记录型、AND 型、信号量集，每次都保留前者的机制并修补其缺陷，用**计数 + 阻塞队列**统一表达资源的可用量与等待关系。

## 死锁的处理

> section_id: basic-os-process-deadlock_handle
> kp_ids: [os.process.deadlock]
> primary_kp: os.process.deadlock

**死锁**：一组进程互相持有对方所需的资源并循环等待，若无外力则都无法推进。与**饥饿**（长期得不到资源）和**死循环**（程序逻辑问题）不同，死锁是资源分配不合理所致。

**四个必要条件**（同时满足才可能死锁）：

- **互斥**：资源在一段时间内只能被一个进程使用。
- **请求和保持**：进程持有部分资源的同时又请求新资源。
- **不可剥夺**：已获得的资源不能被强行夺走，只能主动释放。
- **循环等待**：存在进程—资源的循环等待链。

**处理策略**：

- **预防**：破坏四个条件之一。破坏互斥（如用 SPOOLing 把独占设备改造为共享）、破坏请求和保持（一次性分配全部资源）、破坏不可剥夺（允许剥夺）、破坏循环等待（资源有序分配）。
- **避免**：在分配前判断是否会导致系统进入不安全状态（如银行家算法）。
- **检测与解除**：用**资源分配图**能否完全简化来判定；解除手段有资源剥夺、撤销进程、进程回退。
- **忽略（鸵鸟策略）**。

**思想**：四类策略从严到宽，系统的并发性依次增大，所付出的代价与实现复杂度也各不相同。

## 银行家算法的安全条件

> section_id: basic-os-process-bankers_safety
> kp_ids: [os.process.bankers]
> primary_kp: os.process.bankers

**安全状态**：若系统能找出一个**安全序列**，即按该序列依次为各进程分配资源、每个进程都能顺利完成，则系统处于安全状态。安全序列可能不止一个。

**安全判定条件**：对某个尚未完成的进程 Pi，若其**尚需资源**不超过**当前可用资源**与**所有已完成进程将释放的资源**之和，则 Pi 可被加入序列并视为完成、释放其已占资源；重复此步，能纳入全部进程则为安全。

**结论**：系统处于安全状态时一定不发生死锁；进入不安全状态时**可能**发生死锁。因此银行家算法在每次分配前试探是否存在安全序列，仅在安全时才真正分配。

**同类资源的一个充分条件**：设 N 个进程各需 R 个同类资源，当系统提供 K = N × (R − 1) + 1 个该类资源时，无论如何申请都不会死锁。
