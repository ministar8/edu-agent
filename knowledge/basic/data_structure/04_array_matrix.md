## 学习目标

- 理解多维数组的存储映射思想

---

## 数组与存储映射

> section_id: basic-ds-array-storage
> kp_ids: []

**基本思想**：多维下标映射到一维地址；行优先或列优先决定扫描序。

**为什么**：物理内存是线性的，必须有确定映射才能 O(1) 计算地址。

**特点**：随机访问快；大小固定；中间插入删除代价高。

---

## 压缩存储

> section_id: basic-ds-array-compressed
> kp_ids: [ds.array.compressed]
> primary_kp: ds.array.compressed

**定义**：对含规律的矩阵只存有效元素，并建立下标到存储位置的映射。

**为什么**：n 阶对称矩阵可少存约一半；稀疏矩阵中大量为零，全存浪费空间。

**机制**：

- 对称/三角：按规则只存下三角或上三角
- 稀疏：三元组（行、列、值）或十字链表等，换映射效率

**思想**：**用映射换空间**；是否压缩取决于「零/对称元素比例」与「是否频繁随机存取」。

---

## 对称 / 三角 / 稀疏矩阵

> section_id: basic-ds-array-forms
> kp_ids: [ds.array.symmetric, ds.array.triangular, ds.array.sparse, ds.array.compressed]
> primary_kp: ds.array.compressed

**对称矩阵**

**定义**：A[i][j] = A[j][i]。只需存一半加对角线。

**三角矩阵**

**定义**：上三角或下三角区域全为常数（常为 0）。存非常数区 + 常数。

**稀疏矩阵**

**定义**：非零元素个数远少于总元素。

**特点**：

- 三元组存「谁非零」，适合按非零元遍历
- 若需任意 A[i][j]，需索引结构辅助定位
- 压缩提高空间利用率，可能牺牲随机访问常数

**思想**：压缩存储的本质是**承认结构冗余**，并用额外索引/公式恢复下标语义。

## 一维数组的地址计算

> section_id: basic-ds-array-address-1d
> kp_ids: []

**定义**：一维数组把同类型元素连续存放，逻辑位序与物理地址顺序一致。

设元素大小为 L（即 `sizeof(ElemType)`），起始地址 LOC 为首元素 a₀ 的地址：

LOC(a_i) = LOC + i × L

**机制**：任意元素的地址只由「起始地址 + 下标 × 元素大小」决定，可一次算出，不需要逐个跳过前面的元素 —— 这正是**随机访问**的根据，存取任一元素均为 O(1)。

**下标约定**：若下标从 1 开始（第 i 个元素），则其地址为 LOC + (i − 1) × L。数组元素的物理位置只与下标有关，与该元素的值无关。

---

## 二维数组的行优先与列优先映射

> section_id: basic-ds-array-address-2d
> kp_ids: []

**定义**：二维数组可理解为「元素是一维数组的一维数组」，逻辑上是二维表，物理内存却是一维的，因此需要一条把二维下标线性化的映射规则。

设二维数组 A 有 M 行 N 列，元素大小为 L，起始地址 LOC 为 A[0][0] 的地址。

**行优先映射**（先按行号从小到大，行内再按列号从小到大）：

LOC(A[i][j]) = LOC + (i × N + j) × L

**列优先映射**（先按列号从小到大，列内再按行号从小到大）：

LOC(A[i][j]) = LOC + (j × M + i) × L

**机制（通用推导）**：地址 = 起始地址 + (完整跳过的元素个数 + 块内偏移) × L。

- 行优先：跳过前 i 行（每行 N 个元素），再加本行第 j 个 → 偏移 = i × N + j
- 列优先：跳过前 j 列（每列 M 个元素），再加本列第 i 个 → 偏移 = j × M + i

**下标不从 0 开始时**：若行下标范围是 [c₁, d₁]、列下标范围是 [c₂, d₂]，记列数为 d₂ − c₂ + 1，行优先下

LOC(A[i][j]) = LOC + ((i − c₁) × (d₂ − c₂ + 1) + (j − c₂)) × L

**特点**：行优先与列优先的差别只是**扫描序**不同，二者都能 O(1) 算出任意元素地址；选哪一种取决于访问模式（按行遍历还是按列遍历）以及与所用语言/库的存储约定是否对齐。

## 对称矩阵的存储映射

> section_id: basic-ds-array-symmetric-map
> kp_ids: [ds.array.symmetric]

**定义**：n 阶方阵 A 若满足 A[i][j] = A[j][i]，则称其为对称矩阵；其上三角与下三角互为转置。

**机制**：对称性意味着只需存**下三角（含主对角线）**；上三角的元素由 A[i][j] = A[j][i] 从对应的下三角元素读出，无需单独存储。

**存储规模**：下三角元素个数 = 1 + 2 + … + n = **n(n+1)/2**（完整 n 阶方阵需 n² 个）。

**映射公式**：把下三角按**行优先**存入一维数组 B，矩阵下标 i、j 从 1 起，B 的下标从 0 起（B[0] 存 A[1][1]）：

- i ≥ j（下三角区与对角线）：k = (i − 1)·i / 2 + (j − 1)
- i < j（上三角区，借助对称性改用 A[j][i]）：k = (j − 1)·j / 2 + (i − 1)

**推导**：第 i 行之前已有 i − 1 个完整行，共 1 + 2 + … + (i − 1) = (i − 1)·i / 2 个元素；行内再数本行第 j 个。上式是「先行求和 + 行内偏移」的写法定型，因数组下标从 0 起，末位减 1。

**思想**：对称矩阵用约一半的空间（n(n+1)/2）换掉冗余的转置副本，同时用分段求和公式把二维下标映射为一维下标，从而在压缩后仍保留 O(1) 的按 (i, j) 访问能力。

## 三角矩阵的存储映射

> section_id: basic-ds-array-triangular-map
> kp_ids: [ds.array.triangular]

**定义**：**下三角矩阵**指主对角线以上的元素全为同一常数 C（通常为 0）；**上三角矩阵**指主对角线以下的元素全为同一常数 C。

**机制**：与对称矩阵不同，三角矩阵的两半并不相等，因此不能靠对称性丢区；除存三角区外，还需**额外一个单元**存放常数 C。

**下三角矩阵**（存下三角 + 常数 C，行优先，B 下标从 0 起）：

- i ≥ j：k = (i − 1)·i / 2 + (j − 1)
- i < j：k = n(n+1)/2（常数 C 所在的位置）

存储规模 = n(n+1)/2 + 1。

**上三角矩阵**（存上三角 + 常数 C，行优先，B 下标从 0 起）：

- i ≤ j：k = (i − 1)·(2n − i + 2) / 2 + (j − i)
- i > j：k = n(n+1)/2（常数 C 所在的位置）

存储规模 = n(n+1)/2 + 1。

**推导（上三角）**：第 i 行从 a_{i,i} 起共 n − i + 1 个元素；其前面 i − 1 行的元素个数为 n + (n − 1) + … + (n − i + 2) = (i − 1)·(2n − i + 2) / 2，本行内偏移为 j − i。

**思想**：压缩的收益来自「大批元素取同一常数值」；代价是那个常数必须单独占位，且映射公式要分「三角区内 / 区外」两支。

## 三对角（带状）矩阵的存储映射

> section_id: basic-ds-array-tridiagonal-map
> kp_ids: []

**定义**：三对角矩阵（又称带状矩阵）中，非零元素只集中在以主对角线为中心的 3 条对角线上，其余元素全为 0，即仅当 |i − j| ≤ 1 时 A[i][j] 才可能非零。

**机制**：把 3 条对角线上的元素按**行优先**压入一维数组 B，其中 A[1][1] 存于 B[0]。

**映射公式**（矩阵下标 i、j 从 1 起，B 下标从 0 起）：

k = 2i + j − 3

**推导**：第 1 行有 2 个元素，其余每行 3 个；前 i − 1 行共 3(i − 1) − 1 = 3i − 4 个元素，A[i][j] 是本行第 (j − i + 2) 个，故其序号为 (3i − 4) + (j − i + 2) = 2i + j − 2，数组下标从 0 起再减 1。

**反向映射**（已知存储下标 k，求 i、j）：

i = ⌊(k + 1) / 3⌋ + 1，j = k − 2i + 3

**存储规模**：约 3n − 2 个元素（第 1 行与第 n 行各 2 个，中间各行 3 个），远小于 n²。

**特点**：三对角矩阵仍能由 (i, j) 在 O(1) 时间内定位，按公式随机访问的能力得以保留。

## 稀疏矩阵的存储映射

> section_id: basic-ds-array-sparse-map
> kp_ids: [ds.array.sparse]

**定义**：非零元素个数 t 相对元素总数 s 非常少，即 s ≫ t 的矩阵。

**机制**：不再按位置做公式映射，而是「**只记非零元**」，并额外维护索引结构：

- **三元组表**（顺序存储）：每个非零元记下 (行, 列, 值)，另存矩阵的行数、列数与非零元个数
- **十字链表**（链式存储）：把行链表与列链表结合起来，便于按行或按列插入与遍历

**特点**：

- 存储量与非零元个数 t 成正比，而不与 n² 成正比
- **丧失随机存储**：不能由 (i, j) 直接算出地址，取单个元素需沿索引结构查找，代价不再恒定
- 适合「按非零元遍历」的运算（转置、加减、相乘），不适合频繁随机定位

**思想**：压缩的收益取决于**稀疏程度**；稀疏矩阵把「公式映射」退化为「索引查找」，是用查找时间换存储空间的典型取舍。
