## 顺序查找与折半查找

> section_id: basic-ds-search-linear
> kp_ids: [ds.search.seq, ds.search.binary_search]
> primary_kp: ds.search.binary_search

**顺序查找**

**定义**：从一端依次比较，直到命中或到端点。

**特点**：实现简单；适用任意线性存储；平均与规模同阶。

**折半查找**

**基本思想**：在**有序且可随机访问**的序列上，比较中间元素，把搜索区间每次减半。

**为什么**：有序性使「排除一半」成为可能，比较次数与 log n 同阶。

**条件**：有序 + 顺序存储（链表折半需代价）。动态插入破坏有序维护成本。

## 分块查找

> section_id: basic-ds-search-block
> kp_ids: [ds.search.block]
> primary_kp: ds.search.block

**定义**：把数据分块，块间有序、块内可无序；先定块，再块内找。

**为什么**：折半要求全序且随机访问；分块在「插入成本」与「查找速度」之间折中。

**思想**：**索引 + 顺序**两级结构——索引定范围，细节用简单方法。

## B 树与 B+ 树

> section_id: basic-ds-search-btree
> kp_ids: [ds.search.b_tree, ds.search.b_plus_tree]
> primary_kp: ds.search.b_tree

**定义**：多路平衡查找树；结点含多个关键字与多棵子树；所有叶结点在同一层。

**为什么**：磁盘/外存按块读写，**降低树高**等于减少 I/O 次数。二叉树在大数据量下太高。

**机制思想**：

- 结点内关键字有序，子树对应区间
- 插入/删除通过结点分裂与合并维持平衡
- B+ 树：关键字作索引，数据/记录集中在叶层，叶层链接便于范围扫描

**特点**：B 树常作**索引结构**；B+ 树更利于「范围查询 + 顺序遍历」。

## 散列表

> section_id: basic-ds-search-hash
> kp_ids: [ds.search.hash]
> primary_kp: ds.search.hash

**定义**：用散列函数把关键字映射到表位置，理想 O(1) 查找。

**为什么**：比较查找存在下界思想；若只需「在不在」，可用地址直接定位。

**机制**：

- 散列函数压缩关键字空间到表地址
- 冲突不可避免：链地址（同义词链）或开放定址（探查）
- 装填因子影响冲突与查找长度

**思想**：**用函数计算换比较次数**；代价是冲突处理与散列函数质量。稳定查找效率依赖分布与装填程度，不是绝对 O(1)。

## 平均查找长度（ASL）

> section_id: basic-ds-search-asl
> kp_ids: [ds.search]
> primary_kp: ds.search

**定义**：平均查找长度（Average Search Length, ASL）是查找过程中关键字比较次数的平均值，是衡量查找算法效率的主要指标。

**公式**：ASL = Σ P_i·C_i（i = 1,2,…,n）

- n 为数据元素个数；
- P_i 为查找第 i 个元素的概率（各元素等概率时 P_i = 1/n）；
- C_i 为查找第 i 个元素所需的比较次数。

**各方法的 ASL**：

- **顺序查找**：成功 ASL = (n+1)/2；失败 ASL = n+1（设置哨兵时）。
- **折半查找**：判定树是平衡二叉树，树高（≈比较次数）= ⌈log₂(n+1)⌉ 或 ⌊log₂n⌋+1，成功 ASL 与 log₂n 同阶；判定树中失败结点共 n+1 个。
- **分块查找**：ASL = L_I + L_s，L_I 为索引表的平均查找长度，L_s 为块内的平均查找长度。设表长 n、分为 b 块、每块 s 个元素（n = sb）：
  - 索引用顺序查找：L_I = (b+1)/2，L_s = (s+1)/2，故 ASL = (b+1)/2 + (s+1)/2；
  - 当 b = s = √n 时 ASL 取最小，ASL_min = √n + 1；
  - 索引用折半查找：L_I = ⌈log₂(b+1)⌉。
- **散列表**：查找效率与元素个数 n 无关，只取决于**装填因子 α = 表中记录数 / 表长**，α 越大冲突越多、效率越低。查找成功 ASL 的分母为关键字个数，分子为各关键字比较次数之和；查找失败 ASL 的分母为散列函数能映射的地址数，分子为各地址探测到空位的次数之和。

## 查找方法复杂度对比

> section_id: basic-ds-search-complexity
> kp_ids: [ds.search.seq, ds.search.binary_search, ds.search.block, ds.search.b_tree, ds.search.b_plus_tree, ds.search.hash]
> primary_kp: ds.search.binary_search

| 查找方法 | 存储 / 前提 | 平均时间复杂度 | 平均查找长度 ASL |
|---|---|---|---|
| 顺序查找 | 顺序或链式，无有序要求 | O(n) | 成功 (n+1)/2 |
| 折半查找 | 关键字有序 + 顺序存储（随机存取） | O(log₂n) | ≈ log₂(n+1) |
| 分块查找 | 块间有序、块内可无序（索引顺序） | O(√n)（s = √n 最优） | √n + 1 |
| B 树 / B+ 树 | 多路平衡、叶同层，面向外存块 | O(log n)，与树高同阶 | — |
| 散列查找 | 散列函数 + 冲突处理 | 理想 O(1) | 由装填因子 α 决定 |

**说明**：折半查找要求随机存取，故只适合**顺序存储**，不适合链式存储；B 树、B+ 树把结点宽度与磁盘块对齐以降低树高，从而减少 I/O 次数。

## B 树的阶与关键字数

> section_id: basic-ds-search-btree-order
> kp_ids: [ds.search.b_tree, ds.search.b_plus_tree]
> primary_kp: ds.search.b_tree

**阶的定义**：m 阶 B 树中，任一结点孩子数的最大值为 m，故一个结点至多含 m−1 个关键字。

**m 阶 B 树的结构约束**：

- 每个结点至多 m 棵子树、m−1 个关键字；
- 根结点若非叶，至少 2 棵子树；
- 除根外的非叶结点至少 ⌈m/2⌉ 棵子树，即至少 ⌈m/2⌉−1 个关键字；
- 孩子数 = 关键字数 + 1（每个关键字把值域切成若干段，逐段对应一棵子树）；
- 所有叶结点（失败结点）在同一层；含 n 个关键字的 B 树有 n+1 个失败结点。

**B 树与 B+ 树的结点数关系**：

- B 树：n 个关键字对应 n+1 棵子树；非根内部结点关键字数范围 ⌈m/2⌉−1 ≤ n ≤ m−1，根为 1 ≤ n ≤ m−1。
- B+ 树：n 个关键字对应 n 棵子树；非根内部结点关键字数范围 ⌈m/2⌉ ≤ n ≤ m，根为 1 ≤ n ≤ m。
- B+ 树所有关键字均出现在叶层且叶层顺序链接，分支结点只作索引，故更适合范围查询与顺序遍历。

**高度与 I/O**：含 n 个关键字的 m 阶 B 树，其高度与 log_m n 同阶（不计失败结点层）；树高越小，外存访问次数越少。
