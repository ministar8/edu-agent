## 树的基本概念

> section_id: basic-ds-tree-tree_concept
> kp_ids: []
> note: 导论性内容，不为目录强行创建 KP

**定义**：树是 n（n≥0）个结点的有限集合。n=0 为空树；非空树有且仅有一个根结点，其余结点可分为若干互不相交的子树。

**为什么需要树**：线性结构只能表达「一对一」；树表达**一对多**的层次关系，如文件系统、组织架构、语法树、索引结构。

**术语**：

- 度：结点的子树个数；树的度 = 各结点度的最大值
- 深度 / 高度：根为第 1 层，向下累加
- 路径与路径长度：结点序列与边数
- 森林：若干互不相交的树的集合

**性质（一般树）**：树中结点数 = 总度数 + 1（根无父边）。

## 二叉树

> section_id: basic-ds-tree-binary_tree
> kp_ids: [ds.tree.binary_tree]
> primary_kp: ds.tree.binary_tree

**定义**：每个结点至多有两棵子树（左、右），且子树有左右之分，次序不可颠倒。

**为什么用二叉树**：结构简单、性质清晰；许多树形问题可转化为二叉树（树⇄森林的二叉树表示）；查找与排序树均建立在二叉树之上。

**特殊形态**：

- 满二叉树：每层结点数达到最大
- 完全二叉树：编号与同深度满二叉树一一对应（缺编号靠右）
- 平衡二叉树、二叉排序树等：在二叉树上附加性质（见后文）

**存储**：

- 顺序存储：完全二叉树可紧凑放在数组中（下标关系明确）
- 链式存储：二叉链表（lchild, data, rchild）最常见

**核心机制**：左右子树递归定义——许多算法（遍历、求深度、复制）都建立在**递归拆解**上。

## 二叉树的性质

> section_id: basic-ds-tree-binary_props
> kp_ids: [ds.tree.binary_tree, ds.tree.complete]
> primary_kp: ds.tree.complete

**定义 / 场景**：二叉树与完全二叉树在结点数、深度、度上有确定的数值关系。

**为什么**：这些性质描述了二叉树的结点数量、层数和结构之间的关系，是理解完全二叉树、顺序存储以及相关算法的基础。

**基本公式**：

1. 第 i 层至多有 2^(i-1) 个结点（i≥1）
2. 深度为 k 的二叉树至多有 2^k − 1 个结点
3. 叶结点数 n0 = 度为 2 的结点数 n2 + 1，即 n0 = n2 + 1
4. n 个结点的完全二叉树深度为 ⌊log₂ n⌋ + 1
5. 完全二叉树中，对结点 i（按层序编号）：左孩子 2i，右孩子 2i+1，父结点 ⌊i/2⌋

**思想**：优先用 **n0 = n2 + 1** 与**顺序编号**做计数与定位，避免逐个枚举。

## 二叉树遍历

> section_id: basic-ds-tree-traversal
> kp_ids: [ds.tree.traversal, ds.tree.binary_tree]
> primary_kp: ds.tree.traversal

**定义**：按某种规则访问树中每个结点一次且仅一次。二叉树由根、左子树、右子树三部分构成。

**为什么**：把非线性结构变成线性序列，是查找、构树、序列化的基础。

**四种基本思想**（以根的访问时机区分）：

| 遍历 | 规则 | 递归思想 |
|---|---|---|
| 先序 | 根 → 左 → 右 | 先处理根 |
| 中序 | 左 → 根 → 右 | 左子树结束后处理根 |
| 后序 | 左 → 右 → 根 | 子树全部结束后处理根 |
| 层序 | 逐层从左到右 | 借助队列，非递归 |

**机制**：

- **递归**：三种深度优先遍历的递归式几乎相同，只交换「根」的位置
- **非递归**：用栈模拟递归；层序用队列
- **唯一性**：先序+中序、或后序+中序，可唯一确定一棵二叉树（仅先序+后序不行）

**公式 / 思想**：

- 树中所有「递归算法」都可看成对三元组（根, 左, 右）的重排
- 由遍历序列还原树：先找根（先序首个 / 后序末个），在中序里划分左右子树，递归

## 线索二叉树

> section_id: basic-ds-tree-threaded
> kp_ids: [ds.tree.threaded]
> primary_kp: ds.tree.threaded

**定义**：二叉树中有大量空链域。利用空指针存放**遍历前驱/后继**，得到线索二叉树。

**为什么**：在不建栈的前提下，按遍历次序找前驱/后继，降低遍历开销。

**机制**：

- 规定空 lchild 指向遍历序列中的前驱，空 rchild 指向后继
- 增加 ltag / rtag 标记指针是「孩子」还是「线索」
- **中序线索二叉树**最常见：适合按中序序列前后移动

**思想**：用**空间冗余指针换时间**；线索顺序依赖**所选遍历**，不是唯一的树结构。

## 树、森林与二叉树

> section_id: basic-ds-tree-forest_convert
> kp_ids: [ds.tree.forest_convert]
> primary_kp: ds.tree.forest_convert

**定义**：树或森林可以与二叉树**一一对应**（兄弟-孩子表示法 / 左孩子右兄弟）。

**为什么**：用二叉树的存储与遍历算法处理一般树，统一处理森林。

**机制**：

- **树 → 二叉树**：每个结点保留与**长子**的边作左孩子；右指针指向**下一个兄弟**
- **森林 → 二叉树**：先按兄弟链成「树」，再按上述规则；或把各树根视为兄弟
- **二叉树 → 树/森林**：逆变换

**性质**：

- 对应的二叉树中，结点的**左子树**来自原树的子树，**右子树**来自原树的兄弟
- 原树/森林的先根遍历 ≈ 对应二叉树的先序；原树后根遍历 ≈ 对应二叉树中序

## 二叉排序树

> section_id: basic-ds-tree-bst
> kp_ids: [ds.tree.bst]
> primary_kp: ds.tree.bst

**定义**：二叉排序树（BST）为空，或满足：左子树所有关键字 < 根；右子树所有关键字 > 根；左右子树亦为 BST。

**为什么**：按「大小」组织数据，插入与查找平均可到 O(log n)（树平衡时）。

**机制**：

- 查找：从根比较，小走左、大走右，直到空或命中
- 插入：查找失败的插入点作为新叶子
- 删除：叶子直接删；单支接子树；双支可用中序前驱/后继替代后再删

**性质 / 复杂度**：

- 中序遍历 BST 得**递增有序序列**
- 平均查找长度与树高相关；最坏（退化成链）O(n)

**思想**：**有序性写进结构**；有序数组的折半在链式结构上变成「树上路径」。与折半查找对比：BST 动态插入容易，但可能退化（引出 AVL/红黑树思想）。

## 平衡二叉树

> section_id: basic-ds-tree-avl
> kp_ids: [ds.tree.avl]
> primary_kp: ds.tree.avl

**定义**：平衡二叉树（AVL）是任意结点左右子树高度差的绝对值 ≤1 的 BST（或空树）。

**为什么**：防止 BST 插入有序序列后退化为链表，保证查找为 O(log n)。

**机制**：

- 平衡因子：左树高 − 右树高，取值 −1 / 0 / 1
- 插入破坏平衡时，对**最小不平衡子树**做旋转（LL / RR / LR / RL 四种）
- 旋转后仍保持 BST 中序有序

**公式 / 思想**：

- 记住：**旋转改变的是指针，不改变中序遍历的有序性**
- 四型判定：看「插入位置在不平衡结点的哪一侧的哪一侧」

**性质**：高度为 h 的 AVL 树，结点数约为斐波那契规模，故高度 O(log n)。

## 哈夫曼编码

> section_id: basic-ds-tree-huffman
> kp_ids: [ds.tree.huffman]
> primary_kp: ds.tree.huffman

**定义**：哈夫曼树是带权路径长度 WPL 最小的二叉树（最优二叉树）。哈夫曼编码由此构造，用于不等长前缀编码。

**为什么**：高频字符用短码、低频用长码，使**加权平均编码长最短**；且前缀码可译、无歧义。

**机制（构造）**：

1. 每个字符作一棵只有根的树，权为频次
2. 每次选权最小的两棵树合并，新根权为左右之和
3. 重复直到只剩一棵树
4. 左 0 右 1（可约定相反），根到叶的路径即编码

**公式 / 性质**：

- WPL = Σ wᵢ × lᵢ（权 × 深度）
- 哈夫曼树中只有度为 0 和 2 的结点；n 个叶子 ⇒ 2n−1 个结点
- 相同权值集合的哈夫曼树**不唯一**，但 WPL 唯一

**思想**：贪心——每步合并当前最小；与「归并排序」中的多路合并思想相通。
